Compiling matplotlib from source via pip on Termux is notoriously tricky because it requires C extensions (Freetype and libpng), and pip often fails to map the native paths inside Android's internal storage. [1, 2] 
To build it cleanly for your targeted Python 3.12.12 environment, follow this structured setup.
Before trying to run any compilation commands, you must provide the toolchain with system libraries and a Fortran/C compiler layout: [1] 

# Update and grab underlying native build tools
pkg update
pkg install build-essential clang pkg-config ninja tuple-repo
# Install necessary development headers for Matplotlib 
pkg install freetype freetype-dev libpng libpng-dev fftw libzmq libzmq-dev

Because Termux doesn't use standard Linux directories (like /usr/include), pip and setuptools will frequently fail with standard #include <ft2build.h> or missing asset flags. You have to force-feed the standard Termux environment variable prefixes explicitly: [1] 

# Inject the Termux local paths so the compiler spots the headers
export CFLAGS="-I$PREFIX/include/freetype2 -I$PREFIX/include"
export CPPFLAGS=$CFLAGS
export LDFLAGS="-lm -lcompiler_rt -L$PREFIX/lib"

matplotlib requires numpy already built and active in your local schema. Ensure you target its compilation first before starting the graphics stack: [3] 

# Upgrade foundational packaging components
pip install --upgrade pip setuptools wheel cython
# Install numpy ahead of time 
pip install numpy
# Trigger the native matplotlib build engine
pip install matplotlib

If you run into architectural errors during compilation, you can leverage precompiled binaries. The Termux User Repository (tur-repo) manages historical build variations. If you run it natively inside a matching environment via: [4] 

pkg install tur-repo
pkg install matplotlib

The repository engine automatically maps it seamlessly to your underlying environment configurations. [5, 6]
