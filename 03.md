To build a Python wheel (.whl) for a completely foreign environment like Termux 32-bit ARM (armv8l) inside an x86_64 system like Google Cloud Shell (shell.cloud.google.com), you cannot just run standard pip wheel. Termux uses a highly specific Android environment layout (/data/data/com.termux/files/usr), paths, and cross-compilation quirks. [1] 
The reliable way to automate this in Google Cloud Shell is by pulling the official termux/termux-docker multiplatform emulator environment, passing the target architecture layout (arm), setting up emulation wrappers (qus via QEMU), and pulling down your specific commit history right before Python 3.13 took over. [2, 3] 
Below is an automated, self-contained shell script layout. It installs the emulation engine, sets up the 32-bit Arm Android runtime container, runs the compile routine inside, and leaves you with the exact standalone .whl package in your execution directory.
## The Automation Script (build_termux_wheel.sh)
Save the following code inside your Google Cloud Shell environment as a file named build_termux_wheel.sh:

#!/bin/bash# Exit script immediately if any individual step crashesset -e

echo "=== [1/5] Preparing Host Architecture Emulation Engine ==="# Termux docker relies on QEMU binfmt_misc routing to build foreign architectures on x86_64
sudo docker run --rm --privileged aptman/qus -s -- -p arm aarch64

echo "=== [2/5] Creating local target workspace ==="
mkdir -p $(pwd)/output_wheel

echo "=== [3/5] Launching Termux ARM32 Isolation Build Engine ==="# We pull down the official 32-bit arm execution sandbox # We explicitly set pid_max and pass unconfined options to keep 32-bit multi-threading safe
sudo docker run --rm \
  --privileged \
  --security-opt seccomp:unconfined \
  -v "$(pwd)/output_wheel:/output" \
  ghcr.io/termux-user-repository/termux-docker:arm \
  /entrypoint_root.sh bash -c '
    set -e
    echo "=== Inside Sandbox: Updating Termux Environment ==="
    pkg update -y

    echo "=== Inside Sandbox: Installing Python 3.12 Corequisites & Build Essentials ==="
    # Pinning python package setup configurations
    pkg install -y build-essential clang pkg-config ninja tuple-repo
    pkg install -y freetype freetype-dev libpng libpng-dev fftw libzmq libzmq-dev
    pkg install -y python python-pip

    echo "=== Inside Sandbox: Verifying Sandbox Python Target Version ==="
    python3 --version

    echo "=== Inside Sandbox: Upgrading Foundation Pip Tools ==="
    pip install --upgrade pip setuptools wheel cython

    echo "=== Inside Sandbox: Compiling Dependency Matrix (Numpy) ==="
    pip install numpy

    echo "=== Inside Sandbox: Binding Environment Compilation Pointers ==="
    export CFLAGS="-I$PREFIX/include/freetype2 -I$PREFIX/include"
    export CPPFLAGS=$CFLAGS
    export LDFLAGS="-lm -lcompiler_rt -L$PREFIX/lib"

    echo "=== Inside Sandbox: Compiling Matplotlib Wheel Target ==="
    # Forces pip to output a universal binary wheel structure instead of immediate local install
    pip wheel matplotlib --wheel-dir=/output

    echo "=== Inside Sandbox: Done building! ==="
'

echo "=== [4/5] Checking Build Results ==="
ls -lh $(pwd)/output_wheel

echo "=== [5/5] Execution Finished Successfully ==="
echo "Your wheel (.whl) target file is saved and ready for export in: $(pwd)/output_wheel/"

## Execution Steps in Cloud Shell

   1. Create and paste the code into the file:
   
   nano build_termux_wheel.sh
   
   (Paste the script contents above, then save and close using Ctrl+O, Enter, and Ctrl+X).
   2. Grant the file execution permissions:
   
   chmod +x build_termux_wheel.sh
   
   3. Fire off the automated process:
   
   ./build_termux_wheel.sh
   
   
## Fetching the .whl from Cloud Shell to your Android device
Once the script logs Execution Finished Successfully, look at the top right of the Google Cloud Shell window interface. Click the More (three vertical dots) button, choose Download, and enter the full directory path to the newly created file (e.g., /home/yourusername/output_wheel/matplotlib-XXXX.whl) to pull it locally onto your file systems. You can then drop it directly into your local storage and run pip install ./matplotlib-XXXX.whl directly on your device.
Depending on your project, do you need any auxiliary scientific computing dependencies like scipy, pandas, or pillow bundled alongside this compiled wheel, or is matplotlib the final wheel file required for your 32-bit machine?
